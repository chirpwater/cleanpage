# Coding Guidelines

1. Less is More - less code, less features. Add by subtracting.
2. Let the code speak for itself - no comments. Rare exceptions may be warrented.
3. Only add unit tests for functional behavior, critical guardrails, and functional regressions. Do not test cosmetics. Not everything needs a specific test. One e2e test often covers a lot of ground.
4. Clean as you go - if you see something amiss, flag it for fixing right there.
